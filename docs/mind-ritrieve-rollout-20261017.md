# Mind Hook 中文语义召回改造（2026-10-17）

## 最终期望

每条非空用户消息仍通过 Claude 的 `UserPromptSubmit` Hook；从当前用户有权使用、尚未在当前对话链交付的 Memory 中，按**话题与语义**召回最多 4 条。无关时可返回 0 条。不得更改 Memory 原文、写入过程、分支证明、回执、历史时间和隔离边界。默认不把私人记忆上传至第三方推理 API。

**本分支只交付阶段 1**：新的本地中文 embedding 后端与隐私安全的降级诊断；其余阶段没有实现，不得宣称已上线、已全库检索或优于 E5。部署在 Mac 前必须独立验收。

## 阶段 1：替换本地向量编码器（当前 PR）

- 使用 `richinfoai/ritrieve_zh_v1`（MIT，0.3B；官方为 SentenceTransformers，1792 维），不能在旧 E5 推理器里直接替换模型名。
- 在 Mac daemon 保持一个本地 Python worker；仅用本地权重，批量编码查询和未缓存的 Memory，512 条 LRU passage 向量缓存。只向本机、已有的用户私有 UNIX socket 提供分数。
- Python 依赖和模型安装在 `~/.cache/leileios/ritrieve-venv`，不写到仓库或 Railway，也不覆盖 E5。
- `pnpm setup:runtime-breath-ritrieve` 只下载公开模型/依赖并做 embedding smoke test；模型文件原版约 1.3 GB，实际依赖与缓存另占磁盘。
- **现有 daemon 默认仍使用 E5**；验证 Mac 运行环境后才在 daemon 环境中设置 `LEILEI_MIND_EMBEDDING_PROVIDER=ritrieve`、重启 daemon。撤销此变量即可回到 E5。
- 自动 Hook 仍使用原来的两次 Railway 请求的语义回传路径，3.8 秒截止和 800ms 本地 socket 预算未改。本阶段不能承诺每条消息都有语义评分，也没有新增记忆副本。
- `LEILEI_MIND_DIAGNOSTICS=1` 开启固定原因码：`semantic_no_candidates`、`semantic_skipped_budget`、`semantic_scored`、`semantic_rerank_failed`。只记录原因码，不记录用户消息、记忆文本、向量或 ID。

**门槛**：Mac 上准备好依赖后，验证模型确实能在 800ms 的 Hook socket 预算内处理热态查询及缓存候选；在真实消息上对照 E5 的召回相关性。未通过不要启用。

## 阶段 2：稳定语义执行与全库候选（未实现）

当前 `hook.mjs` 先请求 Railway 取得 256 条候选，再到 Mac 评分，最后回 Railway 选定，常常因时间限制跳过语义。下一阶段要：

1. Railway 增加独立、鉴权的只读 Memory 快照/增量同步接口，显式传递版本；Mac 仅在 daemon 运行时缓存当前用户的有效文本和向量，变更时增量更新。**不得**依靠模型分数替代服务端权限校验。
2. Hook 先走本机语义检索，再把候选 ID、文本摘要/版本和分数一次提交 Railway。Railway **重新按实时状态验证**用户权限、有效性、版本、是否已沿当前分支交付及原有签名回执；过期候选不注入。
3. 减少为检索而付出的跨网往返，并把每条消息的 `semantic / fallback / skipped / stale` 原因持久化为只含统计值的可观测指标。不得拿延长 Hook 总超时替代架构修正。

## 阶段 3：召回质量（未实现）

- 检索查询综合最近几轮当前分支对话，辨别“你又这样”的指代，而不是只用最后一句表面字词。
- 调整适用于 ritrieve 分数分布的阈值；不能直接假设旧 E5 的绝对相似度阈值 0.80 通用。
- 采用语义为主、姓名/日期等精确匹配为辅的排序，去重和多样性继续保留；最后真正无关就返回 0 条，不凑满 4 条。
- 不再局限于关键词预选的 256 条；若全库超出实时计算能力，通过**已同步的向量索引**召回，而非逐轮重新编码全库。

## 阶段 4：对照验收与切换（未实现）

- 用户授权的真实消息+记忆构成标注集（同义转述、旧事件、关系变化、指代、否定、关键词干扰）；避免把私人文本放进公开日志或 PR。
- 在相同消息和候选集合下比较旧 E5 与新实现的 `Recall@4`、无关注入比例、空结果正确率、Hook p50/p95 耗时、超时/降级率和索引新鲜度。
- **只有相关率提高、错误注入下降、回执与分支回归通过、延迟未破坏聊天体验**时才打开生产开关。否则保持 E5。
- 建立可立即回退的独立开关，不自动覆盖现有模型或数据库。

## 当前状态

该分支为受控、未合并的阶段 1。未在用户的 Mac 上安装模型，未运行真实 Memory 评测，未启用生产环境、未创建后台自动任务。Mac 实测通过前不能宣称最终效果已经达成。
