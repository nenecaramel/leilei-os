# Toy Cap 50 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raise only the Toy percent software cap from 40 to 50 across the existing LeileiOS and local Toy contracts while preserving all duration, TTL, stop-priority, idempotency, claim/ack, and fail-safe behavior.

**Architecture:** Keep the existing `round(percent * 255 / 100)` BLE mapping and frame format unchanged; change only validation/documentation constants and the database check constraint. Generate the migration number from the latest journal at execution time, then validate the full migration lineage in a disposable database. The local runtime remains isolated from Railway commands during tests and production remains untouched.

**Tech Stack:** TypeScript, Zod, Drizzle/PostgreSQL migrations, Node test runner, Python/Pydantic, Bleak, Railway MCP contract tests.

## Global Constraints

- Production percent remains `1..40` until this Draft PR is separately reviewed and deployed.
- New software cap is exactly `1..50`; `0`, `51`, non-integers, booleans, and arbitrary payloads remain rejected.
- Preserve duration `1..1200`, default `60`, Railway command TTL `10` seconds, stop priority/replacement, idempotency, claim/ack, and fail-safe behavior exactly.
- Do not change BLE frame bytes or introduce official-App protocol/mode behavior.
- Do not modify Universe / Day Space UI or runtime code, merge, deploy, or touch production DB.
