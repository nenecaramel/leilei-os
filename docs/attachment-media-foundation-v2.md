# Attachment / Media Foundation v2

Canonical/draft source → B projector → attachment input carried by visual node → registry → shared media renderer → gallery/system file open. The backend attachment ID, refs and download-slot authority remain authoritative. Presentation preserves the entire canonical descriptor, including unknown future metadata; it never identifies files by filename, MIME, URL or position.

B's attachment input now carries original metadata plus explicit source (authoritative, draft, retained Edit, reserved provider candidate). Ready upload snapshots contribute size/SHA/filename/MIME. Retained Edit descriptors keep provenance, refs and integrity while pending ordinals match the resulting canonical message. Failed uploads retain local draft identity and cannot become retained ready attachments. Provider-send attachments use exactly the same renderer.

User media sits above and outside the text bubble. Text/voice nodes alone form that bubble; attachment-only produces none. Unsupported non-media nodes remain visible outside it. Canonical, pending send and Edit share this structure. Attachments remain in canonical ordinal/draft order; contiguous bitmap groups preserve interleaved file positions.

One bitmap is a responsive square; two use one row, three/four two rows. Groups larger than four cap inline previews at four, with a View all count on the fourth. Center crop stabilizes tall/wide thumbnail dimensions. Fullscreen includes all bitmap attachments in message order and locates the selected authoritative/draft ID. UIKit paging hosts zoom scroll views: one-finger paging is disabled while zoomed; system pinch/pan owns image gestures. Done dismisses without a conflicting custom drag. Rotation refits and centers the image.

MIME/UTType, extension capability hints and authoritative kind identify bitmap candidates. ImageIO decides whether actual verified bytes can be decoded. JPEG, PNG, GIF, WebP and HEIC/HEIF use direct downsampling; GIF/WebP explicitly show a first-frame Still preview. Undecodable/mislabeled images retain a visible file/error/retry path. SVG has its own media descriptor and visible SVG preview/open fallback, never bitmap decoding. System Quick Look may preview it; unsupported SVGs can save/share their verified original. General SVG/WKWebView rendering remains G. Unknown MIME remains a file card with original filename/MIME/size and system capability-based open.

Every remote consumer requests an owned backend download slot, honors method/headers, validates returned attachment identity and canonical integrity metadata, then fetches bytes and verifies byte length/SHA. HTTP response caching/cookies are disabled; only verified originals enter the bounded original cache. Network/integrity failure is never cached; Retry refetches. Completed uploads seed this same cache only after server completion and local integrity verification.

Original bytes cache: bounded 64 MiB in memory plus 256 MiB in the app Library/Caches area, keyed by backend/account scope + attachment ID + size + SHA, with in-flight coalescing. Decoded image cache: separate 48 MiB/64-entry ImageIO cache keyed by the same integrity identity and target pixel size. Thumbnail/message/fullscreen decodes share originals. Decode targets derive from available display size/scale, bounded at 3072 (decoder hard cap 4096). Disk entries use hashed integrity identities and are reverified before reuse; cache corruption deletes the entry and fails visibly before Retry. App restart obtains fresh backend authorization/metadata and reuses valid originals or refetches after cache eviction. No persisted URL, stale preview path or attachment database is introduced.

File cards show middle-truncated filename (extension visible), MIME/type, size, explicit loading/error state, retry and open. Preview files live in a dedicated app-owned temporary area, per-preview UUID directory, with sanitized UTF-8-bounded names preserving extension. A lease retains the path while system preview/share uses it and deletes it on dismiss/release; failed writes remove partial directories. First preview after process restart clears stale app-owned preview residue. Quick Look capability failures visibly offer save/share of verified bytes; download/write failures offer retry.

Composer thumbnails use the same input, dispatch and downsampler. File chips retain filename extension, uploading progress indicator, failure/retry/remove. Composer stores its existing local bytes separately; presentation carries descriptors only. Local draft bytes never masquerade as backend IDs.

Out of scope D–H: tool-result canonicalization/structured tool/search/citation, rich Markdown, Artifact/Resource lifecycle, general web/SVG/chart renderers and mixed-device acceptance. No backend schema/authority or Activity/UI polish. Physical-device acceptance: pending. Before declaring media complete, validate photo counts, files/mixed/attachment-only, optimistic readback/Edit, gallery/zoom/orientation, Quick Look, large/long-name/error/retry and canonical rendering after restart on iPhone.
